{%- comment -%} Overrides minima 2.5's own head include, copied verbatim except for the `?v=` on the stylesheet. WHY. minima links /assets/main.css with no version, GitHub Pages serves it with `cache-control: max-age=600`, and a returning visitor's browser holds the old file. Every CSS change therefore ships in two stages — new markup immediately, new styling up to ten minutes later — and the in-between state is a page styled by rules that no longer match its HTML. filter.md already solved this for the two stylesheets it links itself; main.css is the one minima links, and this is the only way to reach it, since minima 2.5 has no custom-head hook. `site.time` is the build timestamp, so the query changes on every deploy and only on a deploy: readers who have not been away since the last build keep their cached copy. {%- endcomment -%} {%- seo -%} {%- comment -%} The wordmark's X on its own, for tabs and search results. Three files because the three consumers differ: SVG for browsers that take one and scale it cleanly, a 32px ICO for the ones that still ask for /favicon.ico by name, and a 192px PNG for Google Search (which wants at least 48) and for a phone home screen. All three are the same sprite at whole-number scales, so no pixel ever lands off the grid. relative_url keeps them right under a project-pages baseurl, where a bare /favicon.ico is not served at all. {%- endcomment -%} {%- feed_meta -%} {%- if jekyll.environment == 'production' and site.google_analytics -%} {%- include google-analytics.html -%} {%- endif -%}
